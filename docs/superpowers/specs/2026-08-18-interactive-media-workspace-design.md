# 交互式媒体工作区设计规格

日期：2026-08-18

## 目标

把现有静态前端原型升级为可操作的浏览器媒体工作区。本阶段交付以下闭环：

- 素材库、预览区、创作助手三栏可拖动调整宽度。
- 时间线可拖动调整高度。
- 内置演示视频可播放、暂停和定位，预览时间与时间线播放头同步。
- 本地素材目录支持视频、图片和音频文件扫描。
- 时间线区分视频轨道和音频轨道，并支持手动添加、删除轨道。

本阶段不实现完整素材拖入时间线、真实剪切、转码、导出或 AI 上传。这些能力依赖本阶段建立的媒体、播放和轨道模型，后续迭代接入。

## 浏览器边界

应用使用 File System Access API 请求用户授权本地目录。首次使用必须由用户点击“选择素材目录”，浏览器不允许网页静默读取任意磁盘目录。

授权成功后，应用将目录句柄保存在 IndexedDB。后续打开时尝试恢复：

- 权限仍有效时自动扫描目录。
- 浏览器要求重新授权时显示“恢复访问”按钮。
- API 不可用、授权被拒绝或目录为空时保留演示素材，并显示明确状态。

本地文件默认不上传。未来 AI 操作需要上传时，必须以具体素材为单位明确触发。

## 系统边界与模块

### MediaLibrary

`MediaLibrary` 负责目录授权、恢复和扫描，并把浏览器文件转换为统一媒体记录：

```ts
type MediaKind = 'video' | 'image' | 'audio';

interface MediaItem {
  id: string;
  name: string;
  kind: MediaKind;
  file: File;
  objectUrl: string;
  size: number;
  modifiedAt: number;
  duration?: number;
  width?: number;
  height?: number;
}
```

首版根据扩展名和 MIME 类型识别常见格式：MP4、WebM、MOV、JPG、JPEG、PNG、WebP、GIF、MP3、WAV、M4A、AAC、OGG 和 FLAC。稳定 ID 由相对路径、文件大小和最后修改时间组成；素材版本堆栈仍使用现有独立 ID 模型。

对象 URL 在素材移除、目录切换或应用卸载时释放，避免浏览器内存持续增长。扫描错误按文件隔离：单个不支持文件不会中断整个目录。

### WorkspaceLayout

布局状态由顶层工作区统一管理：

```ts
interface WorkspaceLayoutState {
  assetWidth: number;
  assistantWidth: number;
  timelineHeight: number;
}
```

预览区占用三栏中的剩余宽度，因此调整素材库或创作助手宽度会自然改变预览宽度，不再单独保存预览宽度。这样能避免三个相互冲突的宽度来源。

约束：

- 素材库：180–420 px。
- 创作助手：280–560 px。
- 预览区：始终至少 360 px。
- 时间线：200 px 至视口高度的 55%。

拖动时分隔条 1:1 跟随指针，越界时使用渐进阻力，释放后回到合法范围。交互使用 Pointer Events 和 pointer capture，允许在拖动途中反向，不锁定输入。布局在拖动结束时写入 `localStorage`，避免逐帧写盘。

键盘用户可以聚焦分隔条并用方向键每次调整 8 px；按住 Shift 时每次调整 32 px。分隔条使用正确的 `separator` 角色、方向和当前值。

### PlaybackController

播放器状态作为预览区与时间线之间的唯一事实来源：

```ts
interface PlaybackState {
  status: 'idle' | 'loading' | 'ready' | 'playing' | 'paused' | 'ended' | 'error';
  currentTime: number;
  duration: number;
  selectedMediaId: string | null;
}
```

本阶段默认选中内置演示视频并通过原生 `<video>` 播放。播放、暂停、上一帧、下一帧和进度定位均操作同一个媒体元素。时间线播放头读取播放器当前时间；拖动或点击时间线标尺会更新播放器时间。

更新播放头使用 `requestAnimationFrame`，但时间值以媒体元素为准，避免累计漂移。暂停、标签页隐藏或播放结束时停止帧循环。`prefers-reduced-motion` 不影响时间同步，只移除播放头的装饰性过渡。

素材预览规则：

- 视频：显示视频画面和完整播放控制。
- 图片：显示静态图像，禁用播放按钮并展示图片状态。
- 音频：显示音频封面/波形占位，保留播放、暂停和定位。
- 无法解码：显示文件名、类型和可恢复错误，不让整个工作区空白。

### TrackManager

轨道成为编辑器状态中的一等数据：

```ts
type TrackKind = 'video' | 'audio';

interface TimelineTrack {
  id: string;
  name: string;
  kind: TrackKind;
  order: number;
  muted: boolean;
  locked: boolean;
}
```

时间线顶部提供“添加视频轨道”和“添加音频轨道”。命名按类型自动递增，视频轨道显示在上方、音频轨道显示在下方；同类型内保持用户顺序。

删除规则：

- 空轨道立即删除。
- 含片段的轨道弹出确认，明确显示将移除的片段数量。
- 每种类型允许删除到零条；下一次添加继续生成不重复名称。
- 删除轨道进入现有撤销/重做历史，取消确认不产生历史记录。

现有片段从字符串 `trackId` 迁移到轨道表引用。初始化时创建 V2、V1 和 A1 三条轨道，保持当前演示内容的视觉顺序。

## 数据流

1. 应用启动并恢复布局偏好。
2. 尝试读取 IndexedDB 中的目录句柄；无句柄时展示演示素材和选择目录入口。
3. 用户授权后，扫描器异步产出媒体记录并更新素材库。
4. 选中素材后，预览区根据媒体类型切换渲染器。
5. 播放器事件更新统一播放状态；时间线播放头订阅该状态。
6. 轨道增删通过编辑器命令执行，进入撤销/重做历史。

目录扫描状态、媒体播放状态和编辑器历史相互独立：目录授权失败不会破坏时间线，播放器解码失败不会清空素材库，布局调整不会进入剪辑撤销栈。

## 错误与反馈

- 目录权限：区分未选择、需要恢复、被拒绝和浏览器不支持。
- 扫描：展示已发现素材数量和被忽略文件数量；错误文件可单独重试。
- 播放：加载时显示进度，解码失败时显示替换素材入口。
- 删除：只有含片段的轨道需要确认，避免确认疲劳。
- 所有错误都在相关模块内显示，不使用阻塞整个应用的全屏错误页。

## 交互与无障碍

- 分隔条命中区至少 10 px，视觉线保持克制，仅在悬停、聚焦或拖动时增强。
- 拖动期间使用直接跟随；边界使用软阻力；释放后采用临界阻尼回正。
- 所有播放和轨道按钮有明确中文无障碍名称及可见焦点。
- 播放状态不只依赖颜色，按钮图标和文本同时改变。
- 在高对比度和减少透明度模式下使用实色背景与明确边界。

## 测试策略

单元测试覆盖：

- 媒体类型识别和稳定 ID。
- 布局尺寸约束及键盘步进。
- 播放状态格式化、定位和结束状态。
- 轨道添加、空轨道删除、含片段轨道删除及撤销。

组件测试覆盖：

- 两个垂直分隔条与时间线水平分隔条的指针和键盘交互。
- 视频播放/暂停按钮及时间码更新。
- 图片和音频采用正确预览模式。
- 目录权限的四种界面状态。
- 添加、删除视频轨道和音频轨道。

集成验证覆盖：

- 全部 Vitest 测试通过。
- TypeScript 类型检查通过。
- Vite 生产构建通过。
- Chromium 中手动授权测试目录后能发现三类文件。
- 播放演示视频时，预览时间码和时间线播放头一致。

## 完成标准

- 用户无需刷新即可连续调整三栏宽度和时间线高度。
- 布局刷新后恢复到上次合法尺寸。
- 内置演示视频能够播放、暂停、定位并驱动时间线播放头。
- 授权目录中的视频、图片和音频能出现在素材库并进入对应预览模式。
- 用户能够分别添加视频与音频轨道，并按规则安全删除。
- 现有素材版本冻结、版本替换、模型选择和撤销重做行为不回退。
